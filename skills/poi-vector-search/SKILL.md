# 공공 POI 벡터 검색

이 프로젝트는 공공 POI 약 1천만~5천만 건을 가공해 Milvus에서 벡터 검색하고, 반경 및 카테고리로 결과를 제한하는 Python/FastAPI 서비스를 목표로 한다. AI 기능과 추가 필터는 확장 가능하게 설계한다. 아직 선택되지 않은 데이터 원천, 임베딩 모델, 별도 메타데이터 저장소, 배포 방식을 확정된 것으로 취급하지 않는다.

## 작업 방식

1. 실제 데이터의 좌표계, ID 안정성, 카테고리 체계, 갱신 주기, 누락률과 예상 질의 패턴을 확인한다. 미정인 값은 설정이나 설계 선택으로 남긴다.
2. 반경 및 카테고리 검색이 필요하면 [Milvus 검색 설계](references/milvus-query.md)를 읽는다. `GEOMETRY`·`RTREE` 지원 버전을 먼저 확인하고, 작은 표본에서 필터와 벡터 검색을 함께 검증한다.
3. 대량 수집·가공·주입이나 API를 만들 때 [주입과 서빙](references/ingest-and-serving.md)을 읽는다. 1천만~5천만 건을 Python 프로세스에 한꺼번에 적재하지 않는다.
4. 일반 Milvus 조작에는 이 프로젝트의 [milvus 스킬](../milvus/SKILL.md)을, Python 성능·자원·async 구현에는 해당 로컬 스킬을 필요할 때만 함께 참고한다.

## 프로젝트 제약

- POI 위치는 입력 좌표계를 확인해 경도·위도 순서의 WKT `POINT(lon lat)`로 정규화한다. 반경 입력은 미터 단위이며 유한한 수와 허용 범위를 검증한다.
- 벡터 유사도, 공간 필터, 카테고리 필터의 결합 방식과 정렬 기준을 API 계약에 명시한다. 단순 반경 조회와 벡터 상위 K 검색은 결과 의미가 다르다.
- 카테고리 값과 공간 좌표를 사용자 입력으로 받을 때 필터 문자열을 안전하게 구성하고, 좌표 범위·출력 건수·타임아웃을 제한한다.
- 스키마, 인덱스, 파티션, 배치 크기, 동시성은 실제 분포와 지연 시간 목표로 결정한다. 임의의 단일 인덱스나 데이터베이스를 기본 정답으로 강제하지 않는다.
- 구현 결과에는 데이터 정합성(건수·중복·좌표·카테고리), 검색 품질, p95 지연 시간, 인덱스/메모리 사용량을 대표 표본으로 확인한다.
